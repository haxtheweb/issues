# HAX Trademark and Brand Usage

The HAX name, the HAX logo, and the names of HAX ecosystem projects (HAXcms, HAXiam, the DDD design system, and others) identify this community and its software. Apache-2.0 governs the code; this policy governs the names and marks.

## What anyone may do

- Use the HAX name in good faith to refer to the project — blogs, talks, papers, course materials, conference posters.
- Fork, modify, and redistribute the code under the terms of Apache-2.0 (the license travels with the code).
- Say that you use HAX, build on HAX, or provide services for HAX.
- Use the HAX logo to link to the project or identify it in a list of technologies.

## What requires asking first

Open an issue in the unified queue before:

- Using the HAX name or logo in a product name, company name, or domain name that implies the project itself is behind it.
- Redistributing modified versions under the HAX name. Instead, say "built on HAX" or "HAX-based" and describe your changes.
- Using the HAX logo on merchandise, in certifications, or in anything that implies endorsement.
- Displaying the marks in a way that suggests Penn State or the HAX community endorses a product, service, or event.

## Official releases

Official HAX releases are the git tags published from repositories in the `haxtheweb` GitHub organization, and packages published under the `@haxtheweb` npm org. Everything else — vendor packages, 1-click installers, forks, containers built by third parties — is a redistribution, and should be described as such ("HAX 26.x-based image", not "HAX 26.x release").

## Vendors and hosting partners

Vendors (including hosting partners) may state that their service runs HAX, link to the project, and contribute back through the unified issue queue. They may not imply endorsement, certification, or that they publish official HAX releases. Partner listings on project pages are earned through contribution and maintained at the project's discretion — see GOVERNANCE.md for how vendor participation works.

## Attribution requirement

Redistributions should preserve the LICENSE and NOTICES files that ship with the code (Apache-2.0 requires it), which keeps the connection to the project visible.

Questions about this policy: open an issue in the unified queue.
